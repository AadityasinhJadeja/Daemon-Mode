Privacy.

Daemon Mode is designed to keep agent memory under the owner's control. This page explains what can be handled, where it is stored, and the boundaries that apply.

Chrome Web Store Limited Use

Daemon uses browsing activity and website content only to provide its disclosed single purpose: local, owner-controlled memory that the user's chosen AI agents can search through non-destructive tools.

Daemon does not sell this data, use it for advertising or credit decisions, or send it to the developer or other people. Access to the local files follows the owner's macOS permissions.

Daemon Mode's use of information received from Chrome extension APIs adheres to the Chrome Web Store User Data Policy, including its Limited Use requirements.

What can be stored

For pages that pass protection checks, Daemon can store the page URL, title, domain, capture time, extracted readable page text, text length, and local capture metadata in SQLite.

Bounded agent-tool diagnostics can include tool name, status, timing, evidence count, and a bounded query for owner-visible review. Query logs do not store the retrieved evidence snippets.

Private data warning

Daemon does not intentionally store cookies, passwords, form values, or credentials. Page text can still contain sensitive information, so review protection settings before browsing private material.

Where it is stored

Memory is stored locally in a SQLite file. The default macOS path is:

~/Library/Application Support/Daemon Mode/memory.sqlite3

The extension sends allowed page data only to the companion service on the same computer. The service binds to loopback only. Daemon has no account system, cloud database, analytics service, advertising SDK, or remote sync.

Chrome profiles share one macOS-user vault

Chrome profiles enabled under the same macOS user account connect to the same local service and merge allowed captures into one SQLite vault. Separate macOS user accounts have separate default vaults.

Protection happens at three boundaries

  1. Before reading: the extension checks the current page immediately before it reads page text.
  2. Before storage: the local service rejects protected and credential-bearing URLs.
  3. Before retrieval: protection rules are applied again before evidence can reach an agent.

Built-in sensitive categories, site preferences, password/private-page checks, and the owner's blocklist participate in those decisions. If the initial check is unavailable, unsuccessful, or malformed, the extension fails closed and does not read page text.

Protected events can retain bounded diagnostics such as domain, reason, status, and time so the owner can verify that protection happened. They do not retain protected page text.

Agent data access is non-destructive

Agents can search memory, retrieve citation-ready evidence, request an evidence-grounded answer, request an exact agent-safe activity summary, and check bounded protection status.

Agents cannot export, delete, clear, or change protection rules through MCP. Daemon records bounded local query metadata—client, tool, outcome, timing, and evidence count—for the owner-visible activity view, but not returned evidence snippets. An agent with separate shell or filesystem access is outside this MCP-only boundary. The connected agent client and its model can process evidence returned through MCP under that client's own privacy terms.

Optional provider-backed prose

No AI provider is needed for local capture, search, citations, protection, or exact summaries. If the owner explicitly enables a provider, selected evidence and the question are sent to that provider to produce prose. The provider receives only the evidence selected for that request; its own privacy terms then apply.

Correct disclosure

When provider-backed prose is shown, Daemon identifies it as: “Evidence selected locally · answered by [provider].”

Human-owned controls

The local dashboard provides human-only controls to export the SQLite database, permanently delete one capture, clear captures and local agent-query history while preserving protection rules, and add or change protection rules.

SQLite secure deletion, physical row and FTS deletion, database compaction, and WAL truncation reduce recoverable remnants after confirmed deletion. Backups, snapshots, or copies made outside Daemon are outside that guarantee.

Uninstalling the background service does not delete memory. This prevents accidental data loss and lets the owner export or clear it separately.

Removing the extension stops future capture but does not delete the separately stored SQLite vault. Protection reduces exposure but cannot guarantee classification of every sensitive sentence on an otherwise allowed page. A malicious local administrator or process with access to the owner's files is outside the current boundary.

Reporting a privacy issue

Never post real browsing text, URLs, database files, credentials, or API keys. Follow the safe instructions on the Security page.
